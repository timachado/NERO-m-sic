# NERO — Radar, atualizações e publicação

- Radar continua opt-in; usa artistas seguidos, favoritos e histórico e até dois gêneros. A consulta diária é aproximada, não push em tempo real. Primeira consulta bem-sucedida cria referência; novas publicações entram na caixa de novidades e, se permitido, no canal de notificações do Android. Caixa local por conta, limitada a 30, consultável dentro do Radar mesmo sem permissão Android. Não são notificações de qualquer postagem/canal de artista: a fonte atual é a data de lançamento registrada no MusicBrainz.
- Atualizações oficiais: o app consulta o manifesto público GitHub ao retomar e por WorkManager a cada 12h aproximadamente, filtra versão superior, canal estável, destino oficial e formato de hash; alerta do sistema uma vez por versionCode se permitido e diálogo no app. Download via navegador; Android valida assinatura no upgrade. Não instala silenciosamente. Não depende de credencial no APK. O manifesto inicial fica publicado=false, sem anúncio.
- Publicação: depois da aprovação do APK e da primeira configuração comercial, integrar branch à main e executar o workflow manual protegido nero-publish-official com run_id aprovado e confirmação PUBLICAR_NERO. O workflow verifica build, assinatura, aplicação, versão, hash, ancestralidade e publica Release e manifesto. Não foi executado. Nunca publicar builds dev automaticamente.
- WordPress: configurar uma vez o botão de download do cadastro NERO no Core para https://github.com/timachado/NERO-m-sic/releases/latest/download/NERO-Music.apk ou consumir updates/stable.json da main, como no padrão Brother. Esse vínculo no WordPress ainda não foi configurado/verificado; após configurar, o link estável aponta para o APK publicado mais recente sem edição a cada versão. Não modifica preços ou checkout. Não usa credenciais Brother. FCM instantâneo não implementado: esta entrega utiliza consulta periódica e aviso ao abrir. Para push instantâneo será necessária configuração FCM exclusiva NERO e validação de entrega. Nenhum release ou envio foi feito nesta revisão.

## Build 166 — FCM exclusivo
O APK registra FirebaseMessagingService, tópico nero_music_stable_updates_v1, aceita apenas sinal de versão superior e reconsulta manifesto oficial antes de notificar. Consulta periódica permanece como fallback. Preferência independente na Conta; Android exige autorização. A automação envia somente após release e manifesto verificados e registra reserva durável antes do envio; uma falha incerta exige auditoria antes de qualquer reenvio. Configuração necessária no ambiente nero-release: NERO_GOOGLE_SERVICES_JSON para app br.com.timachado.neromusic (projeto exclusivo NERO), NERO_FIREBASE_PROJECT_ID, NERO_FIREBASE_SERVICE_ACCOUNT_JSON e NERO_FCM_ENABLED=true. Não reutilizar conta de serviço do Brother; não habilitar sem verificar projeto, assinatura e recebimento em aparelho. A API GitHub não permitiu consultar metadados de secrets/vars nesta sessão. Não houve envio, publicação ou modificação de WordPress. O link permanente continua dependendo do cadastro inicial do proprietário.
