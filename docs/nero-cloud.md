# NERO Cloud 0.9.40-dev

Manual backup preview for the signed-in Google account. Stores online track references and online playlists only, not audio, local device IDs, history, preferences, credentials or downloads. The upload merges cloud and local references; compare-and-swap revision rejects stale writes through the RPC. Restore merges by playlist ID, keeps local names and order, and can resurrect previously removed items; deletion propagation is not implemented. Each local file uses its existing atomic writer, but both files are not one transaction. If a restore partially fails, repeat the additive merge. Never describe this as automatic or real-time synchronization.

`supabase/setup/nero_cloud_library.sql` is an unapplied deployment draft, separate from existing sharing and app tables. It uses explicit grants, per-owner RLS and invoker RPCs. Direct owner-authorized table writes are possible; revision protection applies to the RPC, not arbitrary API clients. Server-side payload validation bounds the JSON envelope; Android checks individual reference fields. Review quotas, privacy/deletion workflow, direct table privileges and concurrent clients before commercial deployment. Do not apply to existing production infrastructure without explicit authorization. Validate with two test accounts, anonymous denial, cross-account denial, stale revision rejection, restore and retry on a dedicated staging instance. No cloud data has been written.

## 0.9.54 — account integration

Account screen now includes an explicit manual snapshot upload/restore and server plan lookup. Only portable online references are included. Local library files are still device-wide and restoration is additive. Users must confirm before transferring their local references. Logout does not erase local files. The server draft for plans only permits owners to read; clients cannot create or change entitlements. No payment provider, billing or entitlement-based unlock is implemented. Neither SQL draft has been deployed. Before automated two-way sync, implement UID-scoped local storage, opt-in migration of legacy data, revisions/deletion tombstones and conflict handling. Validate independent accounts, offline edits, logout during requests and partial restores. Existing shared Supabase projects/auth settings must not be modified without explicit approval.
