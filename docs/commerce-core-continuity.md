## Decisão para NERO
NERO Commerce Connect 0.1.0 instalado pelo proprietário (print 26/11), atualmente apenas diagnóstico/mapeamento, sem cobrança. Não cadastrar produtos manualmente nem usar plugin para duplicar o catálogo. Evoluir como adaptador fino do Core existente (ou módulo aditivo da versão exata do Core, preservando código de todos os aplicativos).
1. Encontrar cadastro NERO Music em `ti_app`, por identidade inequívoca, reutilizar os produtos vinculados. Se ausente, criação de um cadastro exclusivamente NERO pelo mecanismo já existente.
2. Preços aprovados mensal 990, trimestral 2490, anual 8990 centavos BRL. Não habilitar vitalício. Preservar Free e trial 7 dias, uma vez por conta elegível, sem cobrança automática ao fim.
3. Reaproveitar cadastro, checkout, confirmação e licença central; adicionar suporte trimestral somente após verificar versão real do Core, metadados, duração, checkout, validação do gateway, renovação, cancelamento, painel e API. Não usar preço informado pelo APK para conceder benefícios.
4. Usar Supabase/Auth existente (já compartilhado com outros projetos, conforme proprietário), UID verificado, handoff limitado e espelho isolado de entitlement NERO compatível com `nero_plan_read_v1`. Não criar um projeto novo, não substituir auth, não liberar por retorno de checkout ou e-mail autodeclarado. O trial já preparado no NERO permanece draft, a ser reconciliado com fonte única de autorização.
5. Após confirmar os contratos Core e EBD reais, homologar sandbox: dois usuários, eventos duplicados e fora de ordem, pagamento pendente, sucesso verificado, estorno, cancelamento, expiração, restauração, conta errada e fluxo de retorno. Uma única integração comercial, sem cobrança real até aprovação. Não usar versão histórica como atualização do site.
